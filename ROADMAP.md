# План развития

Пункты ниже — очередь работы, а не уже реализованные функции.

## 1. Завершить локальный MVP

- [ ] Убирать завершённые видео из продолжения и дать возможность начать заново.
- [ ] Добавить ввод прямой HTTPS-видеоссылки и понятные ошибки неподдерживаемых потоков.
- [ ] Проверить обрыв/возврат сети, поворот экрана, уход в фон и восстановление процесса.
- [ ] Доработать интерфейс телефона и планшета, пустые состояния и ошибки хранения.

Готовность: сборка и проверки проходят; сценарии воспроизводимы на устройстве.

## 2. Подключить документированный источник

- [ ] Выбрать API, проверить документацию, условия доступа Android-клиента и лицензии.
- [ ] Разделить каталог метаданных и доступность воспроизводимого видео.
- [ ] Реализовать адаптер последних поступлений, поиска, карточки и вариантов просмотра.
- [ ] Ввести стабильные идентификаторы с учётом источника и обновляемых URL потоков.
- [ ] Добавить дисковый кеш: сначала сохранённые карточки, затем фоновое обновление.
- [ ] Добавить тайм-ауты, пагинацию и обработку недоступного источника.

Готовность: при повторном запуске без сети виден кеш; сбой провайдера не обрушает приложение.
Не обещать поддержку Kodik, Alloha, Lordfilm и других источников до подтверждения доступа.
Общий секрет провайдера нельзя надёжно скрыть в публичном Android-клиенте.

## 3. Совместная и облачная разработка — отложено владельцем

- [ ] Пригласить участника в GitHub.
- [ ] Подготовить и проверить отдельное облачное окружение.
- [ ] Добавить автоматическую сборку, тесты, Lint и выдачу APK.
- [ ] Настроить постоянную подпись и безопасное хранение ключа.
- [ ] Проверить полный цикл при выключенном локальном компьютере.

## 4. Публикация и дальнейшее развитие

- [ ] Проверить лицензии и атрибуции, подготовить политику конфиденциальности по реальному поведению.
- [ ] Открыть репозиторий по решению владельца, подготовить выпуск для пользователей.
- [ ] Рассмотреть Windows-клиент после стабилизации Android и контрактов источников.
