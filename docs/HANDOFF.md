# Вход в проект для нового участника

## Цель

KinoPulse — бесплатный проект с открытым кодом, вдохновлённый сценарием просмотра Seena.
Приоритет — Android APK; Windows позже. Собственный постоянно работающий сервер
и обязательные платные API нежелательны. Карточки должны показываться сразу при запуске,
при повторном запуске будущий сетевой каталог должен восстанавливаться из кеша.

## Откуда продолжать

Начинать с текущего проекта 0.2.0-demo. Первоначальный ZIP Gemini устарел:
после него добавлены постоянное хранение, исправления плеера, Wrapper и проверки.
Не пересоздавать проект по старому описанию или обещаниям первоначального генератора.

Читайте в порядке: README.md → PROJECT_STATUS.md → docs/ARCHITECTURE.md → ROADMAP.md.
BUILD_REPORT.md содержит результаты уже выполненных проверок и их ограничения.
Собственный код — MIT; права на видео отдельные, см. THIRD_PARTY_NOTICES.md.
Установщики Seena и материалы исходной переписки не являются частью этого репозитория.

## Как работать вдвоём

1. Согласовать конкретную задачу и ответственного.
2. Создать ветку от актуального main.
3. Внести изменение, проверить его и описать результат.
4. Открыть pull request; второй участник проверяет код и APK.
5. После принятия объединить изменения и обновить состояние/план проекта.

Чаты разных участников не синхронизируют знания автоматически. Решения, которые влияют
на реализацию, сохраняйте здесь или в задачах репозитория. Общие пароли не нужны.

## Точка остановки подготовки

Владелец попросил подготовить проект и загрузить его в закрытый GitHub-репозиторий,
остановившись перед приглашением второго человека. Приглашение будет выполнено владельцем
либо по его следующему указанию. Codex Cloud, GitHub Actions и выпуск APK не настраивались
в рамках этой подготовки. Тестовый ключ подписи в репозиторий не включён: перед облачными
обновлениями нужно решить вопрос постоянной подписи, иначе обновление поверх старого APK
с другим ключом будет отклонено Android.
